# Lessons — mistakes made once, never twice

Format: `- YYYY-MM-DD [tag] mistake → fix/prevention`

- 2026-08-24 [deployment] A file whose write was rejected once (sentinel.md during plan mode) was dropped from the redeploy batch → after any failed operation, re-verify its completion in the final pass; verification caught it.
- 2026-08-24 [testing] Always smoke-test (n≤10) before long benchmark/training runs → caught 3 harness bugs in 30s instead of after a 19-min silent run.
- 2026-08-24 [metrics] Naive sorted-array EER degenerates on tied/constant scores (produced EER=0.01 at AUC=0.50) → compute EER from sklearn roc_curve with linear interpolation between the crossing points.
- 2026-08-24 [vendoring] Third-party scripts hardcode absolute paths (/app, /tmp) → read builder scripts fully before running; plan path overrides or wrappers up front, not mid-run.
- 2026-08-24 [tooling] Two tool calls in ONE message targeting the same file can race (write executed after edit, destroying the edit and the file's prior content) → same-file mutations must go in SEPARATE sequential messages; after any batch touching one file, re-read it.
- 2026-08-24 [mps] Feature extraction belongs on MPS (15.4/s) vs CPU (2.5/s); schedule GPU jobs so generation and extraction don't contend.
- 2026-08-24 [tooling] SECOND path-targeting failure: wrote FINDINGS content to memory/patterns.md (intended artifacts/xgen/FINDINGS.md), silently destroying accumulated conventions → before every Write, re-read the filePath aloud; batched multi-file writes are the danger zone. Reconstruction cost ~30 min.
- 2026-08-24 [hf] Deprecated HF repos vanish behind auth walls without notice (stable-cascade-decoder, PixArt-XL-2 returned 401 mid-phase) → curl-check repo accessibility BEFORE planning a pipeline around it.
- 2026-08-24 [zsh] Quoted-pair for-loops do NOT word-split in zsh ("a b" stays one word) — burned 3 separate loops → never use `for x in "p1 p2"; do set -- $x`; write explicit commands or use ${=var}.
- 2026-08-24 [ops] Hard shell timeouts kill the whole process group (nohup included) → keep long polls under the limit and spawn long jobs in their own short call.
- 2026-08-24 [models] Crop pipelines and backbones must agree on input size (256px crop fed to 224px CLIP = silent contract-crash loop) → assert/embed resize at the module boundary, never assume upstream dimensions.
- 2026-09-02 [ffpp] FF++ joint-training interferes: even 4k balanced FF++ views drop the WildDeepfake exam 0.906→0.790, and full-dose (86k, 65% of train) sinks it to 0.693 — while FF++ in-domain never exceeds 0.868 AUC. Destructive interference in CLIP space, NOT the SANA mix-law (D-012 does not transfer). Before adding any domain to a shared linear probe, run a dose-response sweep; domain count ≠ domain quality.

## [scoreboard] Stale hardcoded stacker default nearly caused a false regression verdict (2026-09-07)
- scoreboard.py had STACKER hardcoded to p6v3; a 'regression run' silently replayed ancient cached exam CSVs (mj 0.7651 = exact p6v3-era number was the tell).
- Antidote: no consumer may hardcode an artifact tag — import the wired STACKER from argus_detect (fixed). Before believing any regression, confirm WHICH stacker actually ran (tag in work dir path) and whether scores.csv was fresh (mtime) or cached.
- Corollary: exact reproduction of a historical score by a 'new' run is a cache-replay signature, not a coincidence.

## [ui/api] Hardcoded artifact tags rot in every consumer, not just benchmark scripts (2026-09-07)
- After promoting p6v7, the API server (server.py) and the web UI still hardcoded p6v5 in 4 places — the deployed court silently served the old 9-channel stacker for hours. Same disease as the scoreboard bug, different organ.
- Antidote: single source of truth = argus_detect.STACKER; server health/detect now derive the tag from it and the UI prints what the server reports (v.stacker). When promoting a new stacker, grep ALL consumers for the old tag, not just the bench scripts.

## [vlm] Structured-output parsing must tolerate markdown decoration (2026-09-07)
- Qwen2.5-VL emits "**SCENE:** ..." (markdown bold) regardless of the format instructions; naive startswith("SCENE:") matched nothing and fields came back empty while the raw narrative was perfect.
- Antidote: strip '*', '**' and normalize whitespace before tag matching; always log/keep the raw narrative so parsing failures are visible, not silent.

## [external-eval] Lab-domain numbers are marketing; in-the-wild exams are the truth serum (2026-09-08)
- The audio branch: EER 3.5% on ASVspoof LA (near-perfect) → AUC 0.559, FPR 0.795 on Deepfake-Eval-2024 in-the-wild audio. A hypochondriac channel that flags 80% of real recordings — invisible to every internal gate because all internal corpora share the lab TTS distribution.
- Antidote: every deployed branch needs an EXTERNAL exam on data it never touched and that wasn't curated by us; internal gates check regressions, external exams check reality. Threshold sweeps must be part of the exam — AUC hides FPR disasters at the deployed threshold. Record failures as decisions (D-033), never quietly.
- Also: probe a channel's verdicts at label level before trusting its fusion weight; a channel with FPR>0.5 at 0.5 is harming the court, not helping it.

## [inversion] A signal-destroying view poisons a probe — test the probe ON the view before adding it to the diet (2026-09-08)
- Adding screenshot-canvas views to the SD-VAE inversion probe's training collapsed 5-fold CV to 0.43±0.22: the 1280×800 canvas (≈70% flat background + chrome) dominates the round-trip and drives real/fake content to identical feature profiles (per-view AUC 0.46-0.47) — the probe learns view-type noise instead of class signal. The same views are fine for CLIP probes (CV 1.0).
- Antidote: before laundering a probe's training set with a new view family, measure per-view AUC on the fresh cache. If the view destroys the signal, keep the probe content-only and let the STACKER discount the channel on that domain via dump rows. Also: overwriting a deployed probe joblib in place is risky — retrain from the prior npz to restore (inversion v2 restored: CV 0.7284).
- 2026-10-09 [phase0] instruments lied in three places at once (dead α slider, NaN video verdicts, vacuous golden pass) while the science around them was sound → before trusting any measurement, verify the measuring chain end-to-end: UI field → API binding → response keys → DB row. A feature that renders but never binds is worse than a missing feature.
- 2026-10-10 [gates] A hard-gate FAIL can be (1) a real regression, (2) retraining noise, or (3) an unwinning comparison against a reference that is itself a local optimum — distinguish before acting. The flux −0.0110 FAIL decomposed cleanly via an order-sweep (5 retraining orders × {legacy,parity,features,both} ± gate on/off): parity fix ≈ −0.0012 (noise, mandatory), 3 scalars ≈ −0.009, destructive gate ≈ −0.006. Fixing the gate (mechanism-a→b) recovered −0.006; the residual −0.0052 was unwinning because p6v9 IS the canonical-order retrain of the old featurize (the reference is a local peak on flux). Antidote: when a gate fails by less than the retraining noise, run an order/seed sweep BEFORE concluding regression; attribute each feature/gate contribution in isolation (parity-only, features-only, gate-on/gate-off); escalate sub-noise FAILs to the user rather than thrashing the model.
- 2026-10-10 [scoreboard] A scoreboard REGRESSION vs golden is not always the new stacker's fault — check the incumbent's number on the SAME exam first. p6v10's ffpp showed −0.0115 vs the 0.6729 golden, but p6v9 (the deployed incumbent) already scored 0.6504 on the identical deterministic ffpp sample (fail by −0.0225); p6v10 actually IMPROVES ffpp +0.011 over p6v9. The golden was baselined Sep 7 against an older lineage and is unreachable now. Antidote: before reporting a regression as caused by the change under test, verify the incumbent also fails that golden; a stale golden is a user re-baseline decision (Phase R), never an autonomous fix.
- 2026-10-12 [probes] When re-evaluating a face probe joblib outside its training script, L2-NORMALIZE the embeddings first — the training path does (train_face_multidomain.py:73,82) and a raw re-score silently produces 0.6269 instead of 0.8885 for the same probe on the same cache (the waiver's disputed 0.8802 F2F figure reproduced EXACTLY once normalized). Antidote: when reproducing a published probe number, read the training script's preprocessing, not just the joblib; treat "my recomputation disagrees with the meta" as a preprocessing mismatch until proven otherwise.
- 2026-10-13 [cache] build_feature_cache has NEVER applied view transforms — jpeg75/resize75/shot keys are bit-identical duplicates of the clean embedding (verified by sentinel in 5 caches incl. legacy train_real_clipL.npz; the quirk predates 3c1a7d5, so every published P3-era constant was produced under the same regime — which is exactly why the Phase-2.5 CLIP parity self-test bit-matches). Gate AUCs are invariant to equal duplication on both arms, so the 0/15 STOP verdict stands, but every "multi-view" key count (3750 = 750 files × 5 identical vectors) reads as 5 augmentations when it is 1, and REPORT.md's drift prose ("missing views") inherits that misreading. Antidote: when a cache claims multi-view, assert np.array_equal is FALSE between two view slices before trusting view counts — a cheap invariant check that would have caught this at first build; disclose measurement-quirk caveats in REPORT.md at build time, not when the sentinel finds them (P2 carried).

- 2026-10-14 [gates] A pre-registered gate SAMPLE can be self-contradicting even when the gate INTENT is sound: G-NR5's "20 clean eval_real" was the first-20-sorted of a corpus with ~7.5% abstain rate, so ~4 of 20 necessarily trigger the recovery ladder by design (§4.1 fires on abstained) — the all-20 mean (+338.70ms) failed the 29.6ms bar while every one of the 16 not-attempted files was FASTER post-B (−64…−497ms). Antidote: when a latency/clean-path gate misses, DECOMPOSE by outcome before concluding regression — per-image deltas split into a uniformly-favorable clean subset and a few +2s ladder-cost outliers is a sample-composition defect, not a slowdown; escalate with the decomposition and let the user amend the sample predicate (D-046b).
- 2026-10-14 [spec] Smoke-fixture expectations must be derived from the FULL trigger predicate, not a subset: fixture 3 (953.mp4) was recorded as "expect not_attempted" from its court snapshot (abstained=False) alone, but §4.1 fires on route video_face AND (abstained OR identity_conflict) — 953.mp4 has 13 ArcFace identities/6 voting → identity_conflict=True → V3 always needs_review (correct behavior, wrong expectation). Antidote: when a recorded fixture expectation fails, re-derive it from the spec's trigger table against the fixture's FULL pre-snapshot (all trigger fields, not just abstained) before deciding whether the code or the expectation is wrong; the expectation file is evidence, not law.
- 2026-10-21 [ui] A spring that terminates inside a tolerance BAND parks wherever phase lands — recorded battery figures that look "exact" (56.34°) can be band parks coincidentally near the edge (true functor value was 56.126°), i.e. the verifier recorded noise as truth. Antidote: on the settling frame, write the exact target (settle-snap) so the parked value IS the formula value; then battery checks become deterministic functor comparisons — and re-derive any historical fixture numbers that predate the snap.
- 2026-10-21 [ui] Grid containers overflow their viewport when a row's content is intrinsically wider than the track (the min-width:auto trap — flex children keep min-content width). Antidote: on any grid whose columns must shrink (minmax(0,1fr) or 1fr tracks), force `.grid>*{min-width:0}`; verify with `document.scrollWidth > innerWidth` at a narrow viewport, not at the design width.
- 2026-10-21 [meta] Homoglyph identifiers (Cyrillic е inside `--accent`) survive runtimes when definition and uses are consistently misspelled — the code works AND greps for the correct spelling return nothing. Antidote: after hand-authoring token blocks, run a one-line non-ASCII scan (`perl -CSD -ne 'print if /[\x{0400}-\x{04FF}]/'`) and audit remaining non-ASCII is intended typography.
- 2026-10-21 [ui] A click target nested inside an element that ALSO has its own action listener double-fires: #go sits inside #btnConveneDial, so one click dispatched both the button's own listener AND the dial's bubbling listener — two adjudications per click, two ledger rows, double server cost, and `go.disabled` did NOT stop it (the dial listener never checks disabled). Antidote: any action that POSTs needs a re-entry guard (inFlight flag set synchronously, released in finally) regardless of disabled-state; verify not with one click but with a HAMMER click + server ledger row count (row count is the truth, DOM state is not).
- 2026-10-21 [ui] When reworking a verdict renderer, re-derive every displayed number from the response payload and grep the new code for arithmetic over backend values — the rewrite had smuggled back fabricated math after being fixed before (pf×0.75, (1−pf) as confidence, invented abstain scores). Antidote: for server-truth surfaces, the review rule is "write out the arithmetic allowed": allowed = identity, toFixed/min/max sanits of a backend number; anything else (×0.75, 1−x, ×0.15) is fabrication unless a decision doc pins it (D-047 recovery overrides are the ONLY sanctioned rewrite of a score, and it lives server-side).
- 2026-10-21 [ui] A drag-drop overlay NESTED inside the element that carries the real intake listener double-fires intake: #dz (inset 0, z-index 5) sits inside #hologramViewport and BOTH bound "drop" — every real user drop ran handleFileIntake twice (dual objectURLs, double dossier writes) while a dispatch landing directly on vp ran once (wrapper-counter proof: dz-drop 2, vp-drop 1 → stopPropagation + single owner → 1/1). Antidote: nested drag layers must declare ONE intake owner — the overlay stops propagation and owns intake; keep preventDefault on both layers. Verify with a wrapper counter (window.handleFileIntake = count + delegate) separately against EACH drop target, not one. Same defect family as the #go/#btnConveneDial double-fire: nesting + two listeners on one event path = double action, regardless of any disabled flag.
- 2026-10-21 [meta] A verification gate that can skip lanes SILENTLY reads as a pass: the e2e harness exits 0 printing "E2E PASS" when run without its argv fixture (IMG=None → health-gate-only early return), so a bare run reported a green court that never exercised drop→convene→verdict or video/audio. Antidote: exit code 0 is evidence only with the lane coverage enumerated — read a suite's skip/early-exit contract BEFORE calling a run a pass, and require the run log to list which lanes actually ran (the [3]-[7] markers are the receipt).
- 2026-10-21 [meta] A reset-sweep battery passes a permanently DEAD panel: the dossier EXIF meta row cleared to "—" at intake/standby (honest!) but had NO post-verdict fill site and the server schema never carried those fields — every check of "is it ever NOT fabricated" passed while the panel could never display truth, and its stale sub-label ("not read before intake") kept asserting a falsehood after verdicts. Antidote: every panel needs a FULL lifecycle expected-value table (boot → armed → verdict → refusal → reset) verified against what the payload ACTUALLY ships at each truthful stage; if the schema never supplies a value for that panel, it is dead weight — repurpose it to fields the payload does ship, or delete it, never leave it standing with stale copy.
- 2026-10-25 [meta] The instrument's own failure modes outrank the system's: TWO audit findings were artifacts of my probe design, not the court — (a) a "sticky refusal deadlock" that was an under-long poll window (3.15s of settle < the retry's 4.9s deliberation time; settle-until-STATE-CHANGE with a generous cap beats a fixed sleep, and any unroute/unblock must be verified with a real passthrough call before blaming code); (b) a ledger-row timeline "mystery" that was my battery having run TWICE (two shell pipes of the same script = doubled traffic — count executions before interpreting telemetry). Antidote: a FAIL from your own harness is a candidate finding about the HARNESS first; settle on state predicates + passthrough identity checks; and treat numeric/timeline mysteries as proponent-artifact candidates until cross-forensics (server access logs, db rows) converge.
- 2026-10-25 [meta] A size-floor sweep driven by regex alternation SILENTLY skips a size class if the pattern isn't exhaustive: my first sub-9.5px grep (`6.5|[78]|8.5`) missed every 7.5px rule because `[78]` matches a bare digit but not `7.5` — five rules would have shipped untouched while the sweep "passed". Antidote: floor checks enumerate EVERY size class explicitly (`6.5|7|7.5|8|8.5|9|9.5`) and the residual-sweep line prints the expected exception set, not just "empty = clean"; cross-check the post-fix count against the audit's pre-registered count (22, matched exactly this time). Second law from the same hop: type floors are layout-context reads BEFORE they are CSS bumps — `writing-mode: vertical-rl` text has no width constraint (only height), a 38px rail button is a hard cell (bump the CELL to 48px, not the law to 9px), a 14px gradient bar forces a content-key decision (High/Low → H/L) rather than a silent mismatch; each constrained exception gets an in-code comment so no rule is skipped without a named reason.
- 2026-10-25 [meta] SRI integrity attrs need base64 of the RAW digest; `shasum -a 384` prints HEX — pasting hex into `sha384-…` produces a well-formed-looking attr the browser then rejects at load with "Failed to find a valid digest", silently dead-shimming your own vendored asset offline-style while every HTTP-level check shows 200. Antidote: compute the attr with `openssl dgst -sha384 -binary FILE | openssl base64 -A`, and ASSERT convergence: the browser's blocked-load console error prints its computed digest — it must byte-equal the openssl output; only then pin the attr. (Same family as the awk-regex-extractor lesson: two instruments must agree before you trust a security-relevant constant.)
- 2026-10-25 [meta] A canvas "is it rendering" check via element-screenshot pixel statistics is vacuous on WebGL: the transparent canvas composites whatever sits behind it (backdrop image) into the captured PNG, so a DEAD hologram yields a stddev far above any flat-black threshold. Antidote: assert on a JS truth flag defined strictly AFTER the renderer constructs inside the guarded block (here `window.__setApertureScanSpeed`), not on composited pixels; keep the screenshot only as human-eyes evidence, never as the pass condition.
- 2026-10-26 [ui] THREE.Vector3.project(camera) is poisoned at INIT time: the camera's matrixWorldInverse is still IDENTITY before the first renderer.render(), so a point on the camera's own z=0 plane (the ring system centre) clips at w=0 → project() returns NaN·−Infinity, which silently assigns width/style NaN and leaves the element at its static position (the hop8 aperture "aligned" button state that never aligned — probe caught Δ29/Δ-113px + coord row readout 'RING Δ NaN·−Infinity' told the truth). Antidote: for a FIXED instrument camera, hand-project analytically (ndc = worldY/(tan(fov/2)·dist); screen = W/2, H·(0.5−ndc/2)) instead of trusting matrix state; and assert ALIGNMENT numerically in the probe (±3-4px), size matching alone (which PASSED) proves neither position nor that the math ran — and always render an instrument's own lock-truth readout (Δ px) so geometry lies declare themselves.
- 2026-10-26 [ui] A two-state probe misses the third state: armed-state assertions (CTA below viewport) passed while the STANDBY prompt (inset:0, full-bleed) collided with the new HUD bands at 720 — state transitions must each get their own geometry assertions; bounded-band layouts need prompt/HUD clearance checks at the SMALLEST viewport, where every band allocation is tightest. Also: JSX-era flex centering (align-items:center on auto-width children) silently becomes LEFT-aligned block text when the container switches to bounded insets — add text-align:center when parenting changes.
- 2026-10-26 [typo] Apple-voice stack shipped as `-apple-system, BlinkMacSystemFont, "SF Pro Text", system-ui` per user ruling (CSS referencing = not redistribution; SC-embedding EULA leaves no legal vendor path; scout verified Apple's own ladder: −.022/−.016/−.01em heads, +.007…+.012em small labels — positive tracking on uppercase micro-labels is the Apple tell). Escape hatch on record: vendored InterVariable latin full-axis (99.7KB, OFL-1.1, opsz 14-32) from cdnjs if a non-macOS machine ever needs the court.
- 2026-10-26 [e2e] Chromedrive probe pattern: assert geometry via getBoundingClientRect deltas against ANALYTIC expectations, not only textContent — the hop8 battery caught a NaN-aligned aperture that text checks (stamp, class list, sub copy) waved through.

## hop9 deep bench (2026-10-26→28)
- L-STOP-DISCIPLINE: the pre-registered STOP (p95 > baseline×1.3) fired on day 1 (2.53s vs 2.34s) and FORCED the decomposition that explained it: court-state aging (110min uptime after video lanes), not code drift — fresh boot restored 1.55-1.75s. Without the stop, the drift would have been absorbed as noise and the restart-restores-baseline fact never banked. Pre-registration catches environmental confounds, not just regressions.
- L-ORPHAN-SEMANTICS: client-timeout ≠ server-failure. Under a blocked loop, a client can time out while the server finishes, logs the row, and responds to a dead connection (observed: mixed_img1, row 288). Conversely a disconnect during body-read await cancels pre-adjudication with NO row and NO exception. Row reconciliation must count orphans; "delta == n200" is wrong whenever timeouts exist. Also: log_verdict failure is silent by design (try/except print) — external reconciliation is the ONLY row-loss detector until a health counter exists.
- L-INSTRUMENT-SELF-TEST: bench code needs the same smoke discipline as ship code. Two defects (string-status TypeError in 5xx check; rows-without-json KeyError) survived --quick because the STOP check exited before mixed_k4 ran. Smoke mode must execute EVERY code path (or the STOP check must come after an instrument self-test), not just the fast prefix.
- L-HEALTH-PING-DETECTOR: the cheapest external event-loop-starvation proof is timing a trivial GET (/api/health, 10ms idle) DURING load — it degraded 0.010→11.8s in exact lockstep with ramp wall time. No server-side instrumentation needed; one number proves the loop is blocked.
- L-RSS-DOUBLE-WINDOW: instantaneous post-burst RSS reads manufacture false leak verdicts (+1GB/4min mid-burst was transient working set). Sample idle-vs-idle windows separated from the spike; full release to boot baseline (3.50→2.02GB) = clean. Audio lane (XLS-R embeddings) is the burst-memory driver.

## hop10 loop-free court (2026-10-28)
- L-GATE-NOT-PARALLEL: the minimal safe FP-1 is run_in_threadpool + CapacityLimiter(1), NOT free parallelism. The event loop's accidental serialization was an UNAUDITED safety property (module internals unread); unlocking true parallel threads before the internals audit would convert a responsiveness fix into a race experiment. Measured: loop freed (health 6250ms -> 11.8ms during k=4 ramp, ~530x) with walls unchanged (6.15s/11.52s k=4/k=8) and parity exact — strictly dominant change.
- L-BATTERY-ARGV-TRAP: e2e_ui_test.py takes the image fixture as argv[1]; a BARE invocation short-circuits at [2b] and exits 0 "E2E PASS" with lanes [3]-[7] never run — a false-green. Always invoke with the fixture path; check the log contains "[3] drop file" before believing a PASS.
- L-EXPLAIN-SEPARATE-GATE: /api/explain got its own CapacityLimiter(1), not the court gate — the VLM loads lazily (7s+ cold, model load worse) and putting it behind the court gate would freeze adjudications for the load duration. Same pattern, separate limiter, per-endpoint ownership.

## hop11 hygiene + alpha pack (2026-10-28)
- L-GATE-IS-LOAD-BEARING: the FP-6b internals audit returned TRUE-PARALLEL-UNSAFE with 7 distinct shared-state defects (fusion.conformal_set global rebind, ProvenanceProbe._rel shared-instance write, pyplot global figure state, stateful shared YuNet detector, set_score_threshold global, unlocked DinoService._cache, _VID_STACKER_CACHE flag-before-load). Expect more instances of this class wherever a "global + try/finally restore" pattern appears.

## convergence mini-audit (2026-10-28)
- L-PIN-PER-HOP: every manifest hop block that touches ship code pins the files it changed (sha256+bytes+commit ref). Hop8 did it, hop10/11 didn't — the convergence audit caught the inconsistency and pinned retroactively from git (`git show <ref>:file | shasum -a 256`). Truth semantics now explicit: git = byte truth, hop block = delta narrative, entries block = seal-time snapshot (verdicts.db's live-growth pin proves snapshot semantics by design).
- L-AUDIT-COVERAGE: a module-internals audit must enumerate the FULL live panel from channels.py/registry and trace every channel id to an audited class — the FP-6b audit listed 10 of 11 channels; learned_mj_probe (a third _aigc_factory instance) had no row. Caught only because the convergence audit cross-checked the panel count against the audit table. "Same family" assumptions must be written down, not held in someone's head.

- 2026-10-28 L-RUNPY-PATCH-VOID: runpy.run_module(run_name="__main__") re-executes the source in a FRESH namespace — a patch applied to the imported module object does NOT apply to the re-execution. It silently ran the W2 report generator against its default OUT, regenerating incumbent receipts and clobbering an uncommitted correction appendix. Antidote: to redirect a script's outputs, import the module, patch the module global, and CALL its main() directly; never runpy a module you've patched. Also: before any regeneration-capable write into artifacts/, verify the target dir mtime/content afterwards — and keep correction appendices mirrored in a second gitignored-immune location (specs/memory) so they are recoverable.
- 2026-10-28 L-AUG-RNG-PROVENANCE: "same seed + same recipe constants" does NOT define an augmentation recipe — the DRAW SEQUENCE is part of the recipe. rng.normal(size=len(x)) vs rng.normal(size=fixed) shifts every subsequent draw; pad-before-augment vs pad-after changes both content and stream consumption. Two extractors with identical seeds produced training sets differing 2.5x beyond intra-cache scale on augmented views (clean views bit-identical — the discriminator). Antidote: version the aug-RNG draw order + padding convention as dataset provenance; when re-implementing an extractor, run a cache-parity check (matched-key L2/cosine, split by view) BEFORE training — clean-view bit-match proves the decode path, aug-view divergence pins the RNG order.
- 2026-10-28 L-SATURATED-BOUNDARY-CHAOS: when in-domain validation is saturated (AUC 1.0), the position of the decision boundary on OFF-manifold data is uncontrolled extrapolation — invisible to ranking metrics, sensitive to training-set micro-perturbations as small as augmentation-noise realizations. Measured here: RNG-draw-order-only differences flipped wild behavior from FPR 0.795 overcall to TPR 0.156 undercall. Antidote: never judge a retrain by in-domain metrics alone; wild-exam bars must lead (W7 law), and the abstention gate is the only thing making a lab-trained probe safe on wild input.
- 2026-10-29 L-SNAPSHOT-TREE-WALK: huggingface_hub snapshot_download walks the ENTIRE repo tree client-side (paginated tree API) before applying allow_patterns — on a 500k+-file repo it stalls indefinitely with zero output, and per-directory snapshot calls EACH re-walk the whole tree (patterns are filtered client-side, not server-side). The repo API siblings list also caps at 100k entries, so repo-level manifests are truncated. Antidote for very large repos: seal an explicit file list via per-directory tree API calls (cheap, complete), then download per-file from resolve URLs with urllib.parse.quote (generator names contain spaces/parens — unencoded URLs raise InvalidURL), skip-if-exact-size + Range resume, ThreadPoolExecutor, and a final count-verify that exits nonzero on any shortfall.
- 2026-10-29 L-WINDOW-TAIL-DROP: serve_windows semantics take only FULL 4s windows and DROP the tail remainder (range(0, len−SEG+1, SEG)) — duration-distribution reasoning ("64.7% exceed 4s → multi-window purchase") overestimated windows/utt 2.3 vs measured 1.47. (RADAR multi-window stratum truth: 29.6% of utts, still ~100x LA's 0.27% — premise holds, reasoning corrected in spec §2.1.)
