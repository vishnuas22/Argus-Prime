- 2026-10-10 [exams] Every exam script writes to a stamped out dir (--out defaults to <name>_<stacker>_<YYYYMMDD>) and refuses a non-empty out dir before mkdir/scoring unless --force (which resumes/appends). - 2026-10-10 [stacker] Non-destructive conflict gate (mechanism-b): stacker_judge.py sets out_of_conflict = (conflict_metric(survivors) > conflict_p99) but DOES NOT overwrite the stacker's probabilities — the destructive early-return (mechanism-a, forcing uniform 1/3) cost ~−0.006 flux AUC and improved nothing. - 2026-10-10 [restack] Stacker training is ORDER-SENSITIVE: CalibratedClassifierCV(cv=3) uses non-shuffled StratifiedKFold, so fold membership depends on pd.concat row order (CORPORA order vs sorted vs shuffled). Retraining the SAME recipe on the SAME data across 5 equally-valid orders swings flux AUC 0.9336–0.9554 (sd 0.0076). Consequence: the incumbent (p6v9) is the canonical-CORPORA-order draw = often the MAX of its own retraining distribution, so a hard-gate tolerance tighter than the noise floor (−0.005 < sd 0.0076) is unwinnable by ANY retrain. Before trusting a sub-noise gate FAIL, measure the retraining distribution (order-sweep) and confirm the reference is not a lucky draw.

- 2026-10-15 [parity] A parity gate must compare like-for-like: an n=15 harness subset AUC checked against an n=100 scoreboard statistic is unpassable even by the reference itself (its own first-15 restricted AUC = 0.9644 vs full 0.9906, Δ=0.0262 > ±0.02 tol). Before concluding a scoring-harness regression from an AUC delta, (a) recompute the reference's own scores RESTRICTED to the identical images — if it reproduces the measured number, the harness is fine and the GATE sample is wrong (D-048), and (b) check per-image score identity at 1e-4 (30/30 here) as the primary court-reproduction evidence. Antidote: write parity gates as subset-vs-subset with recorded gate_text, never subset-vs-full-set.
